- - **On a screen with no chat.** A home screen can start a run of its own agent and show the chat surfaces that run renders. This part renders them; the [React Native guide](/ag2/react-native#compose-a-screen-with-no-chat) has the whole screen, which starts the run once, shows a spinner while it runs and a retry when it fails, and defines `isChatSurface`:
-     There is no Inspector on React Native. `onError` gets render failures, invalid props, failed events, failed functions that a component called and the operations that the app rejected; a render failure or invalid props that stay the same while the agent sends new content are reported once, and a failed event or function on every call. Operations that the runtime rejected never reach `onError`. They reach the `rejected` and `error` props of the `Wrapper`: the `Wrapper` of `GenerativeUIActivity` for a chat surface, and the `Wrapper` of `GenerativeUISurface` for a surface in a named target. Both default wrappers show a short error line. The exception is a rejected `createSurface`. A named target then keeps its fallback and renders no `Wrapper`; when the app rejected it, `onError` gets it and `<GenerativeUIActivity target="<id>">` shows it. When the runtime rejected it, no activity message is sent for it, so only the model learns of it, in the result of its `render_ui` call, and nothing on the device shows it. The one exception is a `createSurface` with the id of a live surface: the runtime adds that rejection to the live surface, whose `Wrapper` shows it. See [Errors on the device](/ag2/react-native#errors-on-the-device).
